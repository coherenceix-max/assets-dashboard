# 민간임대 분양 알림 설정 가이드

두 가지 알림이 들어 있습니다.

| 기능 | 파일 | 동작 |
|---|---|---|
| ① 매일 자정 뉴스 수집 | `.github/workflows/rental-news-daily.yml` | 매일 00:00(KST) 서울·경기 민간임대 분양 기사 수집 → 텔레그램 |
| ② 카카오톡 오픈채팅 중계 | `.github/workflows/kakao-relay.yml` | 지정한 방에 민간임대 소식이 올라오면 → 텔레그램 |

> **먼저 알아두세요.** 두 워크플로 모두 **기본 브랜치(main)에 있어야만** 동작합니다.
> GitHub Actions는 `schedule`과 `repository_dispatch`를 기본 브랜치에서만 실행합니다.

---

## 1단계. 텔레그램 봇 만들기 (공통, 필수)

1. 텔레그램에서 **@BotFather** 검색 → `/newbot` → 이름 입력
2. 발급된 **봇 토큰**을 복사 (`8123456789:AAH...` 형태)
3. 만든 봇과의 채팅방을 열고 아무 메시지나 한 번 보냅니다 (이걸 안 하면 봇이 나에게 메시지를 못 보냅니다)
4. 브라우저에서 아래 주소를 열어 `chat.id` 숫자를 확인합니다

   ```
   https://api.telegram.org/bot<봇토큰>/getUpdates
   ```

   결과 중 `"chat":{"id":123456789,...}` 의 `id` 가 **채팅 ID** 입니다.
   (그룹방으로 받고 싶으면 봇을 그룹에 초대한 뒤 같은 방법으로 확인 — 그룹 ID는 `-100...` 처럼 음수입니다.)

## 2단계. GitHub 저장소에 값 등록

`저장소 → Settings → Secrets and variables → Actions`

### Secrets 탭 (`New repository secret`)

| 이름 | 필수 | 값 |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | ✅ | 1단계의 봇 토큰 |
| `TELEGRAM_CHAT_ID` | ✅ | 1단계의 채팅 ID |
| `NAVER_CLIENT_ID` | 선택 | 네이버 검색 API 키 (아래 참고) |
| `NAVER_CLIENT_SECRET` | 선택 | 〃 |

**네이버 API 키는 선택이지만 강력히 권장합니다.** 없어도 구글 뉴스 RSS로 동작하지만,
구글 뉴스는 링크가 `news.google.com` 리다이렉트로 나오고 국내 부동산 기사 커버리지가 떨어집니다.
네이버 키가 있으면 **언론사 원문 링크**가 바로 오고 수집량도 훨씬 많습니다.

발급: <https://developers.naver.com/apps/#/register> → 애플리케이션 등록 →
사용 API에서 **검색** 선택 → 발급된 Client ID / Secret 등록. 무료이고 하루 25,000회까지 가능합니다.

### Variables 탭 (`New repository variable`) — ②번 기능용

| 이름 | 값 | 설명 |
|---|---|---|
| `KAKAO_ROOMS` | `수도권 분양정보방` | **감시할 오픈채팅방 이름**. 부분 일치이고 쉼표로 여러 개 지정 가능. 비워두면 모든 방 허용 |
| `KAKAO_REQUIRE_REGION` | `true` 또는 비움 | `true`면 서울/경기 지역명이 있는 메시지만 전달 |
| `KAKAO_REQUIRE_LAUNCH` | `true` 또는 비움 | `true`면 분양/모집 단어가 있는 메시지만 전달 |

> 카카오 중계는 기본적으로 **'민간임대' 키워드만** 있으면 전달합니다.
> 채팅 메시지는 기사 제목보다 짧아 조건을 세게 걸면 놓치기 쉽기 때문입니다.
> 알림이 너무 많으면 위 두 변수를 `true`로 켜서 조여주세요.

## 3단계. ① 뉴스 수집 동작 확인

`Actions → 민간임대 분양 뉴스 (매일 자정) → Run workflow`

- **dry_run 체크** → 텔레그램 발송 없이 로그로 결과만 확인 (첫 테스트 권장)
- **window_hours** → 조회 기간. 처음엔 `168`(1주일)로 넣어 수집이 되는지 확인해 보세요

문제가 없으면 이후 매일 00:00(KST)에 자동 실행됩니다.

### 동작 방식

- **조회 기간**: 기본 26시간. GitHub의 예약 실행은 부하에 따라 수십 분 늦어질 수 있어 여유를 뒀습니다.
  겹치는 기사는 `data/sent_state.json` 이 걸러내므로 **같은 기사가 두 번 오지 않습니다**.
- **필터 조건** (세 가지를 모두 만족해야 발송):
  1. 민간임대 계열 단어 — `민간임대`, `공공지원민간임대`, `장기일반민간임대`, `임대후분양` 등
  2. 분양 시작 신호 — `분양`, `청약`, `입주자 모집`, `모집공고`, `임차인 모집`, `견본주택`, `선착순` 등
  3. 서울/경기 지역명 — 서울 25개 구, 경기 시·군, 주요 택지지구(동탄·광교·다산·운정·별내·판교 등)
- **지방 기사 제외**: 부산·대구·광주광역시 등 비수도권 지명만 잡히면 걸러냅니다.
- 결과가 없는 날은 조용합니다. "오늘 없음" 메시지도 받고 싶으면
  워크플로의 실행 명령에 `--notify-empty` 를 붙이세요.

## 4단계. ② 카카오톡 오픈채팅 중계 설정

### 먼저 — 왜 이런 방식인가

**카카오톡은 오픈채팅방 메시지를 읽는 공식 API가 없습니다.** 카카오 개발자 API의 메시지 기능은
"나에게 보내기 / 친구에게 보내기"뿐이고, 채팅방을 구독하거나 읽어오는 수단은 제공하지 않습니다.
따라서 유일하게 안정적인 방법은 **안드로이드 폰의 알림을 자동화 앱이 가로채 웹훅으로 쏘는 것**입니다.

```
카카오톡 알림 → (안드로이드 자동화 앱) → GitHub repository_dispatch
              → kakao-relay 워크플로 → 필터링 → 텔레그램
```

- **안드로이드만 가능합니다.** iOS는 앱이 다른 앱의 알림에 접근할 수 없어 이 방식이 불가능합니다.
  (아이폰만 쓰신다면, 공기계 안드로이드에 카카오톡을 로그인해 두고 그 폰을 중계기로 쓰는 방법이 현실적입니다.)
- 폰이 꺼져 있거나 인터넷이 끊기면 그 시간의 메시지는 놓칩니다.
- 해당 오픈채팅방의 **알림을 켜두어야** 합니다(방을 음소거하면 알림이 안 와서 중계도 안 됩니다).

### 4-1. GitHub 토큰 발급

<https://github.com/settings/personal-access-tokens/new> (Fine-grained token)

- **Repository access** → Only select repositories → 이 저장소 선택
- **Permissions** → Repository permissions → **Contents: Read and write**
- 만료일은 넉넉히(1년) 설정하고, 생성된 토큰(`github_pat_...`)을 복사해 둡니다.

> 이 토큰은 폰에 저장됩니다. 저장소 하나에만 권한이 있는 fine-grained 토큰을 쓰세요.

### 4-2. MacroDroid 설정 (권장 — 가장 쉬움)

Play 스토어에서 **MacroDroid** 설치 후 매크로를 새로 만듭니다.

**트리거** — `기기 이벤트 → 알림 → 알림 수신됨`
- 애플리케이션: **카카오톡**
- 알림 내용 포함 텍스트: `민간임대` *(폰에서 1차로 걸러 불필요한 호출을 줄입니다)*

**액션 1** — `변수 → 변수 설정` (JSON이 깨지지 않게 본문을 정리)
- 문자열 변수 `msg` 생성 → 값: `{notification_text}`
- 이어서 `문자열 조작 → 바꾸기` 로 `msg` 안의 `"` 를 `'` 로, 줄바꿈(`\n`)을 공백으로 치환

**액션 2** — `연결 → HTTP 요청`
- 방식: **POST**
- URL: `https://api.github.com/repos/coherenceix-max/assets-dashboard/dispatches`
- 헤더:
  ```
  Authorization: Bearer github_pat_여기에토큰
  Accept: application/vnd.github+json
  X-GitHub-Api-Version: 2022-11-28
  ```
- 콘텐츠 타입: `application/json`
- 본문:
  ```json
  {"event_type":"kakao-message","client_payload":{"room":"{notification_title}","sender":"{notification_ticker}","message":"[lv=msg]","timestamp":"{year}-{month}-{dayofmonth} {hour}:{minute}"}}
  ```

**제약 없음 조건** — 매크로 저장 후 활성화. MacroDroid에 **알림 접근 권한**과 **배터리 최적화 제외**를
반드시 허용해 주세요. 안 그러면 백그라운드에서 트리거가 죽습니다.

> 카카오톡 알림의 `제목`은 보통 **방 이름**, `내용`은 **메시지 본문**입니다.
> 그룹/오픈채팅은 기기·버전에 따라 제목이 `방이름` 또는 `보낸사람 (방이름)` 으로 나올 수 있는데,
> `KAKAO_ROOMS` 는 **부분 일치**로 검사하므로 방 이름 일부만 정확히 넣으면 둘 다 걸립니다.

### 4-3. Tasker 를 쓰는 경우

- **Profile** → Event → UI → *Notification*: Owner Application = 카카오톡
- **Task** → Net → *HTTP Request*: Method `POST`, URL·헤더·본문은 위와 동일
  (`%evtprm1`=제목, `%evtprm2`=내용. `Variable Search Replace`로 `"` 와 줄바꿈을 먼저 제거하세요)

### 4-4. 테스트

폰 설정 전에 워크플로만 먼저 확인할 수 있습니다.

`Actions → 카카오톡 민간임대 소식 중계 → Run workflow` → payload 칸에 입력:

```json
{"room":"수도권 분양정보방","sender":"홍길동","message":"동탄 공공지원 민간임대 분양 시작 https://apply.lh.or.kr/abc","timestamp":"2026-08-13 21:05"}
```

텔레그램으로 오면 성공입니다. 그다음 폰에서 실제 메시지로 확인하세요.
폰에서 안 올 때는 `Actions` 탭에 실행 기록이 생겼는지부터 보세요.
- **기록이 없다** → 폰(자동화 앱/토큰/URL) 문제
- **기록은 있는데 텔레그램이 안 온다** → 로그의 "→ 무시" 사유 확인 (방 이름 불일치 또는 키워드 없음)

## 로컬에서 직접 돌려보기

```bash
cd scripts

# 뉴스 수집 (발송 없이 결과만)
NAVER_CLIENT_ID=... NAVER_CLIENT_SECRET=... \
  python3 collect_rental_news.py --dry-run --window-hours 168

# 카카오 메시지 판정 테스트
TELEGRAM_BOT_TOKEN=x TELEGRAM_CHAT_ID=x \
KAKAO_PAYLOAD='{"room":"방","sender":"나","message":"서울 은평 민간임대 분양 시작"}' \
  python3 relay_kakao_message.py --dry-run
```

파이썬 3.11 표준 라이브러리만 사용하므로 별도 설치가 필요 없습니다.

## 키워드 손보기

수집 조건은 전부 `scripts/rental_common.py` 상단에 모여 있습니다.

- `RENTAL_KEYWORDS` — 민간임대 상품군
- `LAUNCH_KEYWORDS` — 분양/모집 시작 신호
- `SEOUL_KEYWORDS`, `GYEONGGI_KEYWORDS` — 지역명 (관심 택지지구를 추가하면 정확도가 올라갑니다)
- `NON_CAPITAL_KEYWORDS` — 비수도권 배제어

수집 기사가 너무 적으면 `collect_rental_news.py` 의 `QUERIES` 에 검색어를 추가하세요.

## 알아두면 좋은 것

- **중복 방지**: 발송한 기사/메시지는 `data/sent_state.json` 에 기록되고 45일 후 자동 정리됩니다.
  이 파일은 워크플로가 자동 커밋하며, 커밋 메시지에 `[skip ci]` 가 붙어 Pages 재배포를 유발하지 않습니다.
- **비용**: 퍼블릭 저장소면 GitHub Actions 사용료가 무료입니다. 프라이빗이면 실행 시간만큼 무료 한도에서 차감됩니다(하루 1분 남짓).
- **예약 실행 지연**: GitHub의 `schedule` 은 정시 보장이 아니라 수십 분 늦을 수 있습니다. 조회 기간 26시간이 이를 흡수합니다.
